## Reproduce, without deployment credentials

From the repository root on Node 22+ with installed workspace dependencies and Docker:

```sh
# Fetch dependencies explicitly; the runner itself never pulls images.
docker pull postgres:17-alpine
docker pull openpolicyagent/opa:0.37.2-static
HARNESS_EVIDENCE_FILE=/tmp/llm-isolated.json \
HARNESS_EXISTING_EVIDENCE_FILE=/tmp/llm-existing.json \
  node magda-llm-services/test/integration/run.mjs --existing-tests
```

See the [harness README](../../../magda-llm-services/test/integration/README.md), [runner](../../../magda-llm-services/test/integration/run.mjs) and [recorded results](../../../magda-llm-services/test/integration/RESULTS.md). The runner starts uniquely labelled, loopback-only PostgreSQL and OPA containers; PostgreSQL uses tmpfs. It generates signing material and passwords, removes inherited PostgreSQL connection/TLS/startup settings, applies fresh service SQL, runs real source services and removes its containers. It neither reads kubeconfig nor writes the demo deployment. An unavailable dependency, skipped component test or failed cleanup is not a pass.

### Dated DSH evidence reused, not rerun

- [#3936 live findings](https://github.com/magda-io/magda/blob/poc/3934-litellm-usage-observer/magda-llm-services/poc/live-findings.md): real Responses tool continuations, including measured4312 input+18 output, with cached/reasoning subsets not added twice; title incomplete terminal with valid usage.

- [#3945 LiteLLM comparison](https://github.com/magda-io/magda/issues/3945#issuecomment-7191934830): three clean cold starts on1.83.14 before its separately merged pin update. This is historical comparison, not three new cold starts in PR6.

**DSH decision recommendation:** a title may retry at most once for a transient transport/5xx failure, not auth/quota refusal, and cancel on shutdown. That policy belongs in the maintained dsh-fork, not special-case accounting in MAGDA. [dsh-fork#38](https://github.com/magda-io/dsh-fork/issues/38) records the proposal/acceptance tests; it is not implemented or silently assumed here.

## Design validation and next production steps

- **Supported:** AUTH-3/4/5/6/7/8/9/10/12, EVAL-1/2/3, MODEL-1/2/3, LIFE-1..5 at the stated test layers, DATA-2/3/4, USE-2..9 and API privacy/usage boundaries. This is scoped evidence, not blanket production support.
- **Needs design change:** METER-4/7 calibrated/incomplete estimates, METER-5 DONE versus Responses terminal evidence, METER-6 DSH retries, MODEL-1 shared global model schema, AUTH-8 broad role explanation, USE-10 unbounded read failures and process-local failure semantics. See the focused [reconciliation proposal](../../investigations/3950-llm-design-reconciliation-proposal.md). Applying it to #3932 requires user go-ahead.
- **Unverified:** fresh Kubernetes packaging/GRANT install, all UI accessibility/recovery cases, full provider matrix, billing accuracy, durable multi-replica settlement and failure gating.

Before production: security review internal-admin/service isolation and logs; resolve [#3969](https://github.com/magda-io/magda/issues/3969) and [#3970](https://github.com/magda-io/magda/issues/3970); qualify real routes in [#3971](https://github.com/magda-io/magda/issues/3971); complete fresh install and full browser/recovery work in [#3972](https://github.com/magda-io/magda/issues/3972); instrument estimate rates, failed writes, recovery probes, cache revocation latency and per-route terminal quality with metadata only. Do not add billing-grade reservations, another PostgreSQL server or Redis as an undocumented shortcut.
